# When Valid Tool Calls Are Scientifically Wrong

### Investigating Semantic Generalization Failure in Small Language Models for Human Performance Science

**Draft — not for external submission.** Status: A0 historical results and the A1 diagnosis are
reported from executed experiments. Sections that describe A2–A5 are labelled as not yet
executed. No claim in this draft has been reviewed for publication.

---

## 1. Introduction

Tool-calling language models are evaluated predominantly on whether they emit a well-formed
call: a valid function name, a parsable argument object and schema-conformant types. That
criterion is necessary and insufficient. In a scientific setting the argument object encodes a
*claim about evidence* — which observations support an analysis, which operation is applicable,
and which inferential levels the data can support. A call can be perfectly serialised and still
be scientifically wrong: it can select the wrong analysis, cite an observation that is not
comparable, or assert a causal claim the design cannot identify.

We report a compact model (3B parameters) that is structurally flawless and semantically wrong
on an operational scientific evaluation. On 96 owner-adjudicated questions rendered exactly as
the deployed runtime renders them, the model produced 96/96 schema-valid tool calls, and 1/96
acceptable scientific actions. Every one of the 24 executable requests was refused or
downgraded. The failure was not a parsing problem, a decoding problem or an infrastructure
problem: the deterministic runtime authorised zero unsafe dispatches, and the constrained
decoder was token-identical to native greedy decoding on all 96 items.

The same checkpoint had earlier scored 255/280 exact action matches on a synthetic
held-out development set generated by the same code that produced its training data. The gap
between those two results — 0.911 and 0.010 on acceptable intent — is the phenomenon this paper
investigates. The contribution is not the observation that a small model failed. It is a
controlled diagnosis of *why*, and what that implies for how domain-specific supervision is
generated and evaluated.

Our contributions are:

1. A **structural–semantic decomposition** of tool-calling competence, in which schema validity,
   action exactness, per-field semantic accuracy and claim preservation are measured and
   reported separately, so that valid serialisation is never credited as reasoning.
2. A **paired factorial diagnosis** (adaptation × representation × decoder) over a purpose-built
   contrastive cohort, with scenario clusters as the unit of inference.
3. A **shortcut audit design** that requires positive evidence of dependence on unintended
   features — restricted-input baselines, single-feature ablations and controlled
   counterfactuals — rather than inferring shortcut learning from poor generalisation.
4. A **prospective methodological correction** to a dataset and training program, recorded
   before the corrected experiments run.

We are explicit about what we do not claim. A confidence interval containing zero is not
evidence of equivalence. A low training loss is not evidence of memorisation. A valid tool call
is not evidence of scientific understanding. A deterministic containment of unsafe dispatch is
not evidence of learned scientific competence.

## 2. Related work

**Tool learning.** Toolformer established self-supervised acquisition of API calls
[@schick2023toolformer]. Subsequent work scaled tool-calling supervision through synthesised
dialogue and API corpora [@liu2025toolace] and standardised function-calling evaluation
[@patil2025bfcl]. This literature is dominated by structural and selection metrics — did the
model call the right function with parsable arguments — evaluated over general-purpose APIs.
Our setting differs in that the arguments are scientific claims whose correctness depends on
study design, not on API semantics.

**Scientific agents.** SciAgent and related systems compose scientific tools into multi-step
workflows [@ma2024sciagent]. These systems typically assume that tool selection is the hard part
and that a well-formed call is a correct call. We show a case where selection is easy and
*semantic adequacy* is hard: the model can name an analysis and still attach it to evidence that
cannot support it.

**Shortcut learning and spurious cues.** Shortcut learning is the reliance on features that are
predictive in the training distribution but not in the intended solution [@geirhos2020shortcut].
Annotation artifacts make supervised models exploit label-correlated regularities in inputs
[@gururangan2018artifacts], and controlled compositional benchmarks expose failures that
in-distribution accuracy hides [@keysers2020cfq; @lake2018scan]. Contrast sets and behavioural
test suites operationalise the same concern as a design discipline
[@gardner2020contrastsets; @ribeiro2020checklist].

Our methodological point is narrow and, we think, under-practised: a generalisation gap is
consistent with shortcut learning but does not establish it. Establishing it requires showing
that predictions *change* when the candidate shortcut is removed or perturbed while the
answer-bearing information is held fixed, and that they do *not* change when the answer-bearing
information changes but the candidate shortcut is held fixed.

**Constrained decoding.** Grammar-constrained decoding guarantees syntactic validity by masking
inadmissible continuations [@geng2023grammar]. A parallel literature documents that format
restrictions can degrade reasoning quality [@tam2024format]. Both are consistent with our
finding that a decoder can raise structural validity while leaving semantics unchanged or worse;
we therefore report the decoder effect as a separate estimand and never fold it into capability.

**Parameter-efficient adaptation.** LoRA and its quantised variant make domain adaptation cheap
[@hu2022lora; @dettmers2023qlora]. Cheap adaptation raises a specific risk in scientific domains:
supervision can teach the *shape* of an answer without teaching the conditions under which it is
warranted. Prior work has documented near-zero held-out loss alongside brittle behaviour; we
avoid interpreting our own low training loss as evidence of either memorisation or competence.

**Abstention and selective prediction.** SelectiveNet formalises abstention as a learned option
under a coverage–risk trade-off [@geifman2019selectivenet]. In scientific tool use, abstention is
not merely an accuracy lever: declining to act on insufficient evidence is itself part of the
correct answer. Our scoring therefore treats "no action" as a first-class gold action rather
than as a missing prediction.

## 3. Scientific computational environment

The system separates four layers, and the separation is the reason a semantically wrong call
can be detected at all.

1. **Measurement authority.** Observations carry registry identities for the metric, protocol
   and acquisition device, plus provenance bindings to immutable synthetic source artifacts.
   Identity is data, not free text; two observations are comparable only when their identities
   agree.
2. **Analysis capability registry.** Each registered analysis class declares its required support
   shape and, where implemented, its registered deterministic operation. Operation availability
   is derived from that registry, never asserted by the model. For the Action track, exactly one
   analysis class (scalar absolute change) with exactly two comparable observations has an
   exposed registered operation; every other class is either deferred, rejected, or implemented
   by an operation outside the model-visible inventory.
3. **Claim authority.** Requested measurement-change and relationship levels are checked against
   the evidence actually selected. A causal-evidence request over a two-point series is
   admissible as a *request* and inadmissible as a *result*.
4. **Runtime authorisation.** A parsed proposal is resolved against the bound request; only an
   authorised operation executes, and only over the selected support.

Two consequences matter for evaluation. First, a model can be scored on scientific intent
independently of whether the runtime would authorise execution — which is what makes
"correct intent for a refused analysis" scoreable. Second, the runtime can guarantee that no
unauthorised computation occurs even when the model is wrong, so safety and competence are
separable measurements rather than one composite score.

The environment is fully synthetic. All scenarios, values, populations and athletes are
fictional and generated by repository code; no empirical athlete data is used, and no claim in
this paper concerns real athletes, real teams or clinical practice.

## 4. Historical experimental methodology and results (A0)

### 4.1 Artifact

The studied checkpoint is a frozen LoRA adapter (rank 16, α 32, dropout 0.05, applied to
q/k/v/o projections; 7,667,712 trainable parameters) on `HuggingFaceTB/SmolLM3-3B` at revision
`a07cc9a0`. It was trained for 510 optimizer steps on 2,800 synthetic examples
(200 per family across 14 families), 385,600 supervised target tokens, target-only
cross-entropy, AdamW at lr 2e-4 for 2 epochs.

### 4.2 Development evaluation (A0.2)

280 held-out examples, 20 per family, generated by the same generator with a disjoint template
bank. Exact full-action match:

| Arm | Exact | Notes |
| --- | ---: | --- |
| Adapted, native greedy | 255/280 | Weak families: causal overreach 7/20, practical meaning 9/20, question-adds-causal 19/20 |
| Adapted, C0 sequence-option ranking | 50/280 | 205 items correct under native but wrong under C0 |
| Zero-shot base, native | 0/280 | 0 structurally valid outputs |
| Zero-shot base, C0 | 0/280 | 280 valid outputs, none exact |

Two details matter for interpretation. The C0 arm ranks whole option strings by sequence
log-probability; it is *not* the token-level grammar mask used operationally, and the two must
not be conflated. And the adapted model's training loss fell from a median 0.131 over the first
20 steps to 0.00064 over the last 20 — a number we report but do not interpret as memorisation.

### 4.3 Operational evaluation (A0.3)

A separately authored cohort of 48 synthetic scenario clusters and 96 questions, owner-
adjudicated before inference, with gold frozen and released only after the output commitment.
Composition: 24 EXECUTE, 57 REFUSE, 15 ABSTAIN. Both decoding arms ran in FP32 on one T4 with
greedy decoding.

| Measure | Result |
| --- | --- |
| Generations completed | 192/192, all terminated at model EOS |
| Structured-output validity | 96/96 in both arms |
| Exact or acceptable intent | 1/96 |
| Execution coverage (expected EXECUTE) | 0/24 |
| Novel-language intent | 0/24 |
| Hazard refusal | 0.750 (cluster-bootstrap 95% LB 0.646) |
| Causal claim preservation | 0.833 (inconclusive) |
| Practical-meaning preservation | 0.417 |
| Unauthorized dispatch | 0 |
| Native vs C1 | Token-identical on all 96 items |

The model collapsed onto 27 distinct output strings per arm. The modal output asserted a scalar
absolute change with `operation: NONE` over every observation, or returned the empty action. All
24 executable requests therefore failed at the deterministic authority layer, not at parsing.
Expected ABSTAIN items produced no acceptable abstention (0/15), although none dispatched.

### 4.4 What the historical comparison can and cannot support

A0.2 and A0.3 differ in at least five ways simultaneously: the evaluation distribution, the
question authorship, the input representation, the claim-request field, and the scoring rule.
The difference between 0.911 and 0.010 is therefore *descriptive*. No isolated causal effect is
claimed from it, and the untouched base model was never run on the A0.3 cohort, so LoRA
attribution is not identified either. A1 exists to isolate these factors.

We note one representation fact that motivates the design. The training request carried an
`objective` field, a free-text `measurement`, constant `available_evidence` and
`missing_evidence` strings, `football_context`, `source_documentation` and a
`comparability_evidence` sentence. The deployed request carries only the question, observation
rows with registry stable ids, and a `requested_claims` object. The shared system prompt referred
to an `objective` field that the deployed request does not contain.

## 5. Diagnosis (A1)

*(Results are inserted from the executed campaign. The design is fixed and frozen in
`experiments/a1/call-manifest-v1.json` before inference.)*

### 5.1 Design corrections applied before observation

Three corrections were recorded prospectively, before any A1 output existed.

**Representation equivalence.** We separate three things that were previously conflated:

- **R-op** — the actual operational request, `BoundRequest.model_request()`, verbatim.
- **R-hist** — the information-equivalent historical rendering. It reproduces the A0.2 field
  structure and free-text register, and adds per-observation human protocol and device labels so
  that it carries the same scientific information as R-op. The historical generator emitted only
  a processing-method label; those added labels are the equivalence repair, not assistance.
- **E-op** — an enriched rendering that adds a fixed, gold-blind objective sentence. This is a
  *separate intervention*, disclosed as semantic assistance, and it never appears in the
  principal comparison.

No arm receives gold-derived analysis labels, expected actions or claim levels. The
`requested_claims` field is empty in both principal arms because the deployed host supplied no
typed claim request — a property of the operational path, not a design choice. Claim
preservation must therefore be inferred from question text, and the arm that populates the field
is a separate diagnostic.

**Shortcut learning requires positive evidence.** Poor generalisation is consistent with
shortcut learning and does not establish it. A1 therefore adds restricted-input baselines
(question-only, observations-only, metadata-only), single-component ablations, and controlled
counterfactuals in which the answer-bearing information changes while a candidate shortcut is
held fixed. The shortcut hypothesis is resolved only by those probes.

**Equivalence is not the absence of a significant difference.** An interval containing zero does
not establish equivalence. Contrasts are classified as improvement, degradation, practical
equivalence within a prespecified ±0.15 margin, or inconclusive. Historical C0 sequence-option
ranking and C1 token-level grammar masking remain distinct estimands and are never pooled.

### 5.2 Cohort

48 newly authored synthetic cases in 24 contrastive clusters of two. Each cluster either holds
the observations fixed and changes the question so that the correct action changes, or holds the
question fixed and changes the observations. Allocation: 16 executable absolute-change cases (8
requiring subset selection among 3–5 observations with distractors), 8 registered-but-not-
exposed analyses whose correct intent names the class with `operation: NONE`, 10 causal or
practical claim-preservation cases, 8 missing-information or abstention cases, and 6
out-of-scope or hazard cases. At least 12 cases use phrasing that appears in no historical
template.

Gold is derived mechanically from a declared intent specification by the same registry function
the runtime uses; questions are authored independently and validated against the frozen manifest.
The manifest is canonical JSON bound to its own digest, and any change to a question, allocation,
observation or gold fails closed before allocation.

### 5.3 Principal factorial

2 adaptation arms (M0 untouched base, M1 step-510) × 2 representations (R-hist, R-op) ×
2 decoders (native greedy, C1 grammar mask) over all 48 cases = 384 generations. Both adaptation
arms share one loaded base, with the adapter disabled through PEFT's own adapter context, so
weights, tokenizer, precision, attention implementation and generation settings are identical
and only the adapter delta differs.

### 5.4 Diagnostic interventions

D1 corrected system instruction (the objective sentence removed, nothing else changed); D2 the
enriched gold-blind objective; D3 a constant, non-gold populated `requested_claims`; D4 human
labels instead of registry stable ids; D5 three fixed few-shot exemplars drawn from A0.2 TRAIN
and never from the cohort; D6 the untouched model on the exposed A0.3 cohort, labelled
retrospective and never final evidence; D7 restricted-input probes over 140 A0.2 HELDOUT rows.

The frozen workload is 1,332 generations across 20 deduplicated conditions, below the
authorised 1,336. Representation, system-instruction and label interventions run on the adapted
model only, because the untouched model is expected to fail structurally and its replication
adds no information about the intervention; the savings fund the three restricted-input probes
that the correction requires. Every registered ablation still appears.

### 5.5 Statistics

The scenario cluster is the unit of inference. Each arm is summarised by an equal-cluster mean
with a 95% percentile cluster bootstrap (10,000 draws, fixed seed). Each paired contrast
resamples whole clusters jointly from both arms. Item-level McNemar results are reported and
labelled non-confirmatory, because items inside a cluster share their scenario. Structural
validity, exact action match, per-field accuracy, observation-reference precision/recall/F1,
claim preservation, refusal, abstention, restricted-input performance, output entropy and paired
effects are reported separately.

## 6. Dataset intervention (A2) — prospective

Not yet executed. The A1 findings determine the primary representation and whether the
correction should emphasise representation repair or shortcut removal. The changes already
recorded against the A2 issue are: a scoped shortcut audit applied where omitted information is
scientifically necessary rather than a universal restricted-input ceiling; a three-part positive
shortcut audit; the deployed representation as the dataset of record; and a prohibition on
gold-derived hints in model-visible fields.

## 7. Comparative training (A3) — prospective

Not yet executed and not authorised. Recorded corrections: attribution of a data effect
requires a matched-budget comparison; schema comparisons must disclose that example exposure,
optimizer budget and target-token exposure are not simultaneously matched when target lengths
differ; and the representation of record follows the A1 recommendation.

## 8. Multi-tool generalisation (A4) — prospective

Not yet executed. The complete multi-tool Action release requires A4. A single-tool checkpoint
may support a separately named experimental result but does not complete the multi-tool track.

## 9. Final evaluation (A5) — prospective

Not yet executed. Recorded corrections: absolute model usefulness and evidence of beneficial

## 10. Discussion

### 10.1 Structural validity is not competence

The central empirical fact is a model with perfect schema validity and near-zero acceptable
intent. Any evaluation that reports only the first number would have rated this checkpoint as
working. The decomposition in Section 5 is what makes the failure visible, and the deterministic
runtime is what makes it *diagnosable*: because authorisation is separate from proposal, a wrong
action is recorded as a wrong action rather than silently executing.

### 10.2 Why "it generalised badly" is not a diagnosis

A development-to-operational drop is compatible with at least four mechanisms: distribution
shift in the input representation, dependence on generator artifacts, genuine capability limits,
and ambiguity in the requests themselves. These have different remedies — representation repair,
data redesign, more capacity, better specification — and a generalisation gap cannot distinguish
them. Distinguishing them requires interventions that hold the others fixed, which is what the
factorial and the ablations are for.

### 10.3 What a low training loss means here

A target-token loss of 0.00064 on 2,800 synthetic rows means the model predicts the training
strings well. It does not mean it memorised them, and it does not mean it learned the rule that
generates them. Both readings are unsupported by loss alone; the shortcut probes and the
held-out contrastive cohort are the evidence that bears on the question.

### 10.4 The role of the deterministic layer

Zero unauthorised dispatches is a property of the runtime, not of the model. We report it
because it delimits harm, and we explicitly do not report it as scientific competence. The same
distinction applies to constrained decoding: 96/96 valid outputs under C1 is a decoder property,
and the token-identical result on A0.3 shows the decoder contributed nothing to semantics.

## 11. Limitations

1. **Synthetic evidence.** Every scenario is fictional and repository-generated. The findings
   concern this task construction, not real athletes, and generalisation to empirical
   performance-science data is untested.
2. **Single checkpoint, single base model.** One adapter on one 3B foundation model. No
   stronger-model comparison is reported; whether the failure is capacity-bound is unresolved.
3. **Cohort size.** 48 cases in 24 clusters bounds the achievable precision. A1 diagnoses; it
   does not qualify a model, and its intervals should not be read as qualification evidence.
4. **Authored questions.** The diagnostic questions were authored for this study. Their
   distribution is not a sample of how practitioners ask.
5. **Historical evidence is partly external.** The A0.2 per-arm counts are recorded from a
   SHA-256-identified private audit rather than re-derived inside the public repository, because
   the real held-out rows and adapter weights remain outside Git. The A0.3 cohort, gold and
   outputs are digest-bound in the same way. Aggregate tables in this paper are computed from
   committed generations wherever those exist.
6. **Causal language.** Section 5 reports paired effects under a factorial design. Those are
   causal claims about *this* model, *this* supervision and *this* cohort. They are not claims
   about language models in general.

## 12. Reproducibility

The repository pins the base revision, the adapter weight digest, the tokenizer files, the
inference package set, the decoding constants and every prompt digest. Case manifests and call
manifests are canonical JSON bound to their own SHA-256. Generation is hash-chained per arm and
resumable; a resumed run never regenerates a committed condition and drops only an unterminated
tail. Scoring is a pure function of committed outputs and frozen gold, so tables regenerate
byte-identically on CPU without a GPU.

Artifacts that must remain outside Git — base weights, adapter weights, real held-out rows and
raw empirical data — are identified by digest and are not required to reproduce the aggregate
tables, which are recomputed from committed generations.
